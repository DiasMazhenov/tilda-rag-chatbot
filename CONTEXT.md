# CONTEXT.md — Tilda RAG Chatbot

## Цель и продукт

Создать многоразовый AI-чатбот для Tilda с первым внедрением на **https://comfortclinic.kz**. Бот отвечает по **опубликованным публичным страницам**, автоматически получает изменения сайта и не требует ручного наполнения базы знаний. Дизайн виджета должен соответствовать сайту клиента. Первоначально RU/KZ, английский можно добавить позже.

**На текущий момент:** только план, не работающий backend, не готовый виджет, не активный crawler.

## Репозиторий

- GitHub: https://github.com/DiasMazhenov/tilda-rag-chatbot
- Репозиторий публичный на момент исходной настройки. **Нельзя хранить секреты, ответы пациентов, сырые страницы с непроверенным содержимым, экспорт приватных данных или индекс до проверки публичности.**
- Название проекта более общее, чем Comfort Clinic: предусмотреть конфигурацию разрешённых доменов, брендинга, языков и API-провайдера. Для MVP жёстко ограничить источник **comfortclinic.kz**, не реализовывать открытый crawler произвольных URL.

## Принятые архитектурные решения

1. Источник истины — только **опубликованные страницы сайта**, доступные без логина по HTTPS.
2. Список страниц через sitemap.xml и ограниченный crawl по URL allowlist.
3. GitHub Actions по расписанию и по ручному запуску: discover → crawl → extract → sanitize → diff → QA → versioned publish. Расписание не гарантирует точную минуту.
4. Производный поисковый индекс **генерируется автоматически** и **не редактируется вручную**. На старте допускается компактный JSON-индекс после очистки; выбор R2/KV/Vectorize отложен до оценки размера данных, затрат и требований к свежести.
5. Chat API — Cloudflare Workers. Секретные API-ключи только в серверных Secrets.
6. Tilda T123 — UI виджета, общение с chat API, ссылки на источники и кнопку записи. HTML/JS не содержит API-токенов.
7. LLM получает только минимальные релевантные фрагменты **проверенного очищенного публичного текста**, рассматриваемые как недоверенные данные, а не как инструкции.
8. **Публичный бот никогда не подключается к административному Tilda MCP**, не имеет инструментов публикации и редактирования, доступа к настройкам сайта, формам и заявкам.
9. Render не обязателен, GitHub не выполняет постоянно работающий backend. Секретный LLM API не вызывать напрямую из браузера.
10. Минимизация данных посетителей: не просить ФИО, результаты анализов, симптомы, телефон, паспорт/ИИН. Не сохранять полные запросы/диалоги в логах по умолчанию.

## Функциональные требования

- Вопросы об услугах, врачах, чекапах, составе программ, ценах, контактах, записи, графике — только при наличии фактов на опубликованных страницах.
- Ответ содержит источники с точными публичными URL. При нескольких версиях не смешивать устаревшие цены.
- При отсутствии достоверного источника: честный ответ «Не нашёл подтверждённую информацию на сайте» + официальный контакт или ссылка на запись (если опубликована).
- Не раскрывать backend prompts/ключи/системные настройки; модель не является источником конфиденциальных данных, так как таких данных в её контексте нет.
- Кнопки «Посмотреть услугу», «Посмотреть чекап», «Записаться» ведут к реально существующим страницам/формам; не имитировать заявку.
- Поддержка русского и казахского (переключение + автоопределение).
- Стиль Comfort Clinic (основной зелёный #004341) для первого внедрения, адаптив 320+ px и клавиатурная доступность.

## Нефункциональные требования

- HTTP backend с rate-limit, ограничением длины сообщения/контекста/числа запросов и дневного бюджета.
- Не исполнять произвольные инструменты по запросу модели; у модели нет shell, файлового или MCP-доступа.
- Fail-closed индексатор: сомнительные страницы отклонять; не публиковать при ошибках sanitizer/QA.
- Проверять: редиректы не выходят за allowlist; HTTPS; DNS/IP (SSRF); content-type; размер ответа; timeout; max pages/depth; canonical URLs.
- Из HTML удалять script/style/noscript, JSON-LD с приватными полями, формы, комментарии, скрытые элементы, неочевидный Tilda служебный код; из видимого текста всё равно фильтровать секреты и PII. Публичность страницы не доказывает отсутствия случайно размещённого секрета.
- Отдельно проверять Zero Block, табы/аккордеоны и разные языки: видимость контента может зависеть от JS.
- Ссылки в финальном ответе проверяются сервером на включение в индекс и allowlist.
- Медицинские вопросы: не ставить диагноз и не назначать лечение; при экстренных симптомах направлять за неотложной медицинской помощью.
- Не собирать пользовательские медицинские данные в аналитике, соответствовать применимому законодательству Казахстана после юридической проверки.

## Что будет считаться готовым

- Изменил/опубликовал цену в Tilda → индекс подхватил новую цену без редактирования JSON вручную.
- Удалил/скрыл страницу → её контент больше не используется.
- Бот даёт ссылки на исходные страницы и не придумывает отсутствующие факты.
- На запрос о приватных API-настройках ответить нечем: секреты не доступны ни LLM, ни поисковому слою.
- Работают RU/KZ, мобильный интерфейс, защита от prompt injection, rate-limit, бюджет.
- Есть тесты и rollback индекса.

## Что делать следующему разработчику

1. Сначала прочитать README.md, docs/ARCHITECTURE.md, docs/SECURITY.md, docs/ROADMAP.md.
2. Проверить фактические публичные sitemap.xml и robots.txt; не предполагать список URL.
3. Выбрать модель/провайдера и задокументировать стоимость, retention, DPA/режим обработки данных.
4. Реализовать наименее привилегированный crawler по одному домену, протестировать на Zero Blocks.
5. Реализовать sanitizer с deny-by-default и тестовыми секретами/PII, только затем индекс и деплой.
6. Не использовать Tilda MCP как прямой retrieval для посетителя и не выдавать коммерческие/медицинские догадки за факты.
7. Обновлять этот CONTEXT.md после важных архитектурных решений.
