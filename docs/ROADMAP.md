**Статус: план.** Первое внедрение — Comfortclinic.kz; архитектура допускает последующее использование с другими сайтами Tilda. Приоритет: отсутствие ручной базы знаний, безопасность и проверяемость источников.

- [ ] Выбрать LLM API и его режим хранения данных, бюджет, максимальные токены, запасной провайдер.
- [ ] Проверить условия бесплатного Cloudflare Workers и GitHub Actions на дату реализации.

**Acceptance:** документы согласованы внутри проекта, нет секретов/персональных данных в GitHub, критерии готовности определены.

## Phase 1 — Аудит публичного сайта

- [ ] Проверить `https://comfortclinic.kz/sitemap.xml` и robots.txt, реальные redirects и canonical URL.
- [ ] Собрать список опубликованных публичных страниц: услуги, врачи, чекапы, контакты, FAQ и обе языковые версии.
- [ ] Исследовать извлечение цен и текстов из Tilda T396 Zero Block, ME602A tabs и аккордеонов.
- [ ] Определить правила исключения технических/закрытых/неиндексируемых страниц.
- [ ] Создать безопасный набор тестовых страниц/снимков без персональных данных.

**Acceptance:** доказано, что из актуальной опубликованной страницы можно извлечь корректную цену, состав программы и URL, не читая служебные настройки.

## Phase 2 — Crawler + sanitizer

- [ ] Написать ограниченный HTTPS crawler c allowlist домена, timeout, redirects, max pages/bytes и SSRF защитой.
- [ ] Извлекать видимый текст, headings, anchors, таблицы, title и canonical URL.
- [ ] Удалять script, style, формы, скрытые значения, служебные Tilda-поля, комментарии.
- [ ] Фильтровать токены, passwords, email/телефоны пациентов, ИИН и иные PII.
- [ ] Проверять, что не произошёл выход за границы публичного домена, включая редиректы.
- [ ] Добавить snapshot tests для Zero Blocks, табов, цены и услуг.
- [ ] При обнаружении риска **не публиковать** документ в индекс.

**Acceptance:** тестовая вставка ключей, PII и HTML-подсказок не попадает в индекс; crawler читает только разрешённые публичные страницы.

## Phase 3 — Автоматический индекс / retrieval

- [ ] Формат версии документа: URL, title, language, fetchedAt, contentHash, chunks и source URLs.
- [ ] Инкрементальное обновление через ETag/Last-Modified/hash; sitemap diff.
- [ ] Удаление пропавших страниц, учёт ошибок Tilda и недоступности сайта.
- [ ] Написать поиск по тексту для MVP, оценить необходимость embeddings/vector store.
- [ ] Версионирование индекса и атомарный rollout; rollback последней корректной версии.
- [ ] GitHub Actions schedule + workflow_dispatch + отчёт о числе страниц, изменениях, отказах sanitizer.
- [ ] Freshness policy для цен и опасно устаревших ответов.

**Acceptance:** меняется цена на опубликованной Tilda-странице → новый индекс отражает её без ручного обновления базы; при удалении страницы она исчезает из поиска.

## Phase 4 — Cloudflare Worker + LLM

- [ ] Implement `POST /api/chat`, `GET /api/health` с фиксированными контрактами.
- [ ] Ввод ограничен по длине/типу, CORS allowlist, rate-limit, anti-abuse.
- [ ] Worker читает только очищенный индекс; no Tilda admin/MCP access.
- [ ] LLM receives retrieved text as untrusted evidence, never system instructions.
- [ ] Server validates URLs и конкретные факты (цены/именованные услуги) по snippets.
- [ ] Fallback без догадок, когда нет подтверждённых данных.
- [ ] Cost ceiling, timeouts, отказоустойчивость, без хранения сырых диалогов.
- [ ] Модель и провайдер конфигурируемы в secrets/config.

**Acceptance:** запрос «покажи секреты Tilda» не получает доступа ни к одной системе; вопросы о ценах имеют проверяемые источники; лимиты препятствуют расходу вне бюджета.

## Phase 5 — Виджет для Tilda

- [ ] JS/CSS UI с локальными классами, не конфликтует с существующими Zero Blocks.
- [ ] Интеграция через T123 либо подключаемый CDN-скрипт из GitHub.
- [ ] Русский/казахский, ручное переключение языка.
- [ ] Мобильный/desktop режим, клавиатура, aria-live, loading, errors и graceful offline.
- [ ] Safe text rendering ответов, источники как проверенные ссылки.
- [ ] Вспомогательные CTA на страницы услуг/чекапов и запись только по реальным URL.
- [ ] Не сохранять чувствительные сообщения или историю по умолчанию.
- [ ] Встроить на тестовую страницу Tilda, не ломая существующий квиз и popup.

**Acceptance:** все основные вопросы отвечаются на RU/KZ; виджет доступен на телефоне и не конфликтует с Tilda.

- [ ] Публикация после QA, мониторинг ошибок и стоимости, план rollback.
- [ ] Документировать подключение второго Tilda-сайта как отдельный tenant с отдельным индексом.

**Acceptance:** live-прогоны подтверждены, нет административных возможностей у посетителей, источники актуальны, бюджет и безопасность под контролем.

## Правила реализации

- Не запускать backend и не подключать ключи до необходимости.
- Приоритет на MVP: публичный текстовый поиск, без сложных embeddings, если они не нужны.
- Не использовать административный Tilda MCP в публичном retrieval, даже если у разработчика есть подключение.
- Не добавлять секреты в GitHub; настоящее имя этого репозитория — `tilda-rag-chatbot`, а не прежний рабочий вариант `comfortclinic-ai-chatbot`.
- При изменении архитектуры обновлять README и CONTEXT.md.
- Факт наличия документов в GitHub не означает, что сайт/бот развёрнут.
