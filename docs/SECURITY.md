# SECURITY.md — модель безопасности

## Цель

Публичный AI-чатбот отвечает на вопросы по сайту **без возможности прочесть или раскрыть секретные сведения, получить административный доступ к Tilda или выполнить команды на сайте**.

Ключевой принцип: **LLM не должен видеть данные, которые ему запрещено раскрывать**. Системный промпт «не раскрывай секреты» — дополнительная мера, а не основная защита.

## Границы доверия

1. **Tilda MCP и администрирование:** приватное пространство владельца. Токены позволяют читать/изменять сайт и не должны появляться в frontend, crawler или публичном chat API.
2. **Публичные HTML-страницы:** недоверенный источник. В них могут случайно оказаться токены, скрытый контент, персональные данные, вредные инструкции.
3. **Индекс знаний:** производные данные только из верифицированного публичного видимого текста. Никаких скриптов, форм, закрытых блоков, сырых дампов и секретов.
4. **Пользовательский чат:** недоверенный текст. Пользователь не может задавать URL crawler, запускать MCP tools или влиять на секреты.
5. **LLM API:** внешний сервис. Передаём только необходимый минимум данных и изучаем политику хранения перед внедрением.

## Threat model

| Угроза | Обязательная защита |
| --- | --- |
| Tilda API/Bearer и LLM API утекли через T123 | Секреты только в Cloudflare Secrets; никогда в HTML/JS/GitHub |
| Prompt injection в опубликованной странице | Считать retrieved text данными; запрет инструментария, разделение ролей, проверка ответа |
| Запрос «покажи конфигурацию сайта/ключи» | Секретов в поисковой системе и LLM контексте нет; бот без админ-инструментов |
| Скрытые данные в Tilda Zero Blocks | Extract visible content only; исключать scripts, forms, hidden, metadata с PII |
| Разработчик случайно индексировал секрет | Fail closed, secret scanner, ручной аудит сомнительных документов |
| SSRF через sitemap, редирект или query | Фиксированный HTTPS allowlist, DNS/IP проверка, ограничения redirect, запрет private/loopback |
| XSS через контент или модель | Text-only рендер, проверенные href, CSP где применимо |
| Выдача выдуманных цен/врачей | Answer grounding; факт цены только из индексированного source chunk |
| Spam/abuse дорогостоящего LLM API | Rate-limit, max tokens, дневной потолок затрат, timeout, anti-bot |
| Утечка диалогов пациентов | No raw chat logging by default; не собирать симптомы и PII; сроки хранения минимум |
| Данные другого сайта в ответах | per-site tenant isolation, source allowlist, отдельный индекс/ключ |
| Устаревший индекс после удаления страницы | TTL, удаление/переиндексация, контроль даты, ограничение stale ответов |

## Доступы

- Public Worker: только чтение очищенного индекса + вызов LLM; нет административного Tilda MCP или GitHub write permission.
- Indexer GitHub Actions: fetch опубликованных страниц и запись **только** в назначенное место хранения индекса.
- Репозиторий GitHub: исходники и docs, без секретов. Сейчас репозиторий **публичный**.
- Cloudflare: LLM ключ, токены для загрузки индекса в Secrets; минимальные права, ротация.
- GitHub Actions: использовать scoped credentials с минимальными правами и маскировать значения в логах.

**Никогда не хранить токен Tilda в публичном repo**, даже если его позже удалить коммитом: секрет уже считается скомпрометированным и подлежит ротации.

## Правила crawler

- Только заранее разрешённый домен comfortclinic.kz в MVP.
- Не переходить на пользовательские URL или ссылки по указанию модели.
- Robots policy, ограничения частоты, таймауты и max bytes; не создавать нагрузку на Tilda.
- Exclude: защищённые страницы, query-токены, скрытые поля и формы, комментарии, инлайн конфиги, скрипты, демо-данные и служебные настройки.
- Сканер секретов и PII применять **до** записи в индекс, не только перед отправкой в модель.
- При сомнениях отклонять страницу или фрагмент, не публиковать исходный HTML как fallback.
- Индекс может храниться приватно даже после очистки; лучше не публиковать весь индекс в GitHub без нужды.

## Защита Chat API

- POST только с JSON определённой схемы, ограничение bytes/length.
- Проверка Origin/CORS **не равна аутентификации**; публичный чат остаётся публичным. Добавить abuse prevention.
- Rate-limit IP/сессии, ограничение длины истории, глобальная квота расходов, concurrency limits.
- Без веб-браузинга произвольных URL, shell, exec, admin tools и инструментов записи.
- Проверка, что ответ ссылается только на фрагменты из текущей версии индекса.
- Если relevant evidence нет или документ недостоверен, возвращать честный fallback.
- Ответ выводить безопасно как текст; проверять ссылки и текст внешних материалов.
- Не доверять ссылкам, которые сгенерировала модель: выдавать серверные URL из approved chunks.

## Медицина и персональные данные

- Бот справочный, не ставит диагноз, не предлагает персонализированные схемы лечения и не назначает анализы.
- Не спрашивать медицинскую историю/телефон/ИИН и не сохранять эти сведения в логах.
- Если посетитель сам присылает чувствительные данные, избегать их хранения, пересылать модели только минимально необходимый обезличенный контекст либо отказывать в обработке.
- Нельзя считать переписку с пациентом медицинской консультацией; при тревожных симптомах рекомендовать неотложную помощь.
- Перед эксплуатацией проверить нормы Казахстана о персональных данных и медицинской тайне, уведомления пользователям, условия LLM-провайдера и сроки обработки/хранения.

## Проверки безопасности перед запуском

- [ ] Сканер обнаруживает тестовые bearer/JWT/API keys, email пациента, ИИН и скрытые поля.
- [ ] Prompt injection на странице не меняет инструкции ответа.
- [ ] Пользовательская prompt injection не даёт выполнить Tilda/MCP или shell.
- [ ] Работает allowlist доменов и блокировка редиректов/SSRF.
- [ ] Worker secrets отсутствуют в frontend/source maps/logs/API responses.
- [ ] Проверены rate limiting, лимит расходов и защита от бурстов.
- [ ] Пользовательские диалоги не хранятся без необходимости.
- [ ] Проверены ссылки и соответствие цен опубликованным страницам.
- [ ] Есть процедура ротации ключей, отката индекса и реакции на инциденты.

До прохождения проверок систему не размещать как публичного AI-консультанта.
